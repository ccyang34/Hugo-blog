# 分类与标签（Tags）生成机制说明

本文档说明 Hugo 博客发布器中**分类（Categories）**与**标签（Tags）**的完整生成逻辑，基于代码实际实现整理。

## 一、整体流程

文章发布时（异步 `process_publish_task` / 同步 `publish_sync`，两套逻辑一致），分类与标签由 **AI 分析 + 后端规则引擎** 共同决定：

```
用户输入 → 抓取/解析 → DeepSeek format_article（AI 分析，产出 title/categories/tags/content）
                                    ↓
                    后端规则引擎（量化强信号判断、兜底、补充标签）
                                    ↓
                    写入 front matter（categories / tags）→ 生成 Markdown 文件
```

## 二、分类（Categories）生成

### 2.1 优先级链（自上而下，命中即停）

| 优先级 | 规则 | 逻辑 | 代码位置 |
|---|---|---|---|
| 1 | **用户指定** | 用户填了分类 → 直接采用，不再调用 AI 分类 | `backend/app.py` L455-457 |
| 2 | **量化强信号规则** | 标题/tags 命中量化关键词 → 归为「量化」 | `backend/app.py` L458-462 |
| 3 | **AI 生成** | 从 10 个预设分类中选择 1-3 个 | `backend/app.py` L463-467 |
| 4 | **兜底** | AI 未返回任何分类 → 「未分类」 | `backend/app.py` L465-466 |

### 2.2 用户指定（最高优先级）

用户在前端手动选择/填写分类时，该分类作为**硬性约束**直接写入，不再调用 AI 判断分类。prompt 中也会注入「用户指定分类（必须遵守）」规则，确保 AI 输出的分类与用户一致（`deepseek.py` 的 `_build_format_prompt`）。

### 2.3 量化强信号规则（第二优先级）

定义于 `backend/app.py` L62-98，用于覆盖用户未指定分类的情况。**标题或 tags 命中任一关键词即判定为量化文章**，分类强制为「量化」，并自动补充「量化」「量化策略」两个标签（`_ensure_quant_tag`）。

### 2.4 AI 分类判定规则（第三优先级）

用户未指定且未命中量化规则时，由 DeepSeek `format_article` 根据正文判定分类。prompt 中的分类规范如下（`deepseek.py` 的 `_build_format_prompt`）：

- **分类规范**：基于以下预设分类的"定位"描述，判断最符合的分类。允许选择多个（最多 3 个），但这要求文章确实跨越了多个领域且相关性都很强。
- **自主创建规则**：如果文章内容确实不属于任何预设分类，根据理解自主创建一个最能代表文章主题的、简洁的分类（要求 2-4 个汉字）。

**预设分类及定位描述（10 个，定义于 `backend/services/base_llm.py` 的 `PRESET_CATEGORIES`）**：

| 分类 | 定位描述（AI 判定依据） |
|---|---|
| 研究报告 | 长篇、深度、结构化的正式报告。 |
| 期货分析 | 针对大豆、油脂、豆油、棕榈油、基差、榨利等期货品种的产业链分析与行情研判。 |
| 市场分析 | 针对股票、宏观经济、各行业资金流向（如 AI 行业资金分析）、市场热点等非期货品种的金融/行情复盘。 |
| ETF投资 | 针对各类 ETF 基金（如宽基、行业、跨境 ETF）的申购赎回、走势分析、配置策略。 |
| 投资策略 | 偏向方法论、配置逻辑、模型工具的使用、避坑指南。 |
| 投资理财 | 泛理财、公募基金、个人财务规划。 |
| 量化 | 量化投资与量化交易：量化策略（多因子、动量、CTA、趋势跟踪、均值回归、套利、网格、高频）、因子模型与因子分析、策略回测与参数调优、量化交易系统与自动化执行、机器学习/深度学习选股与预测、量价与盘口数据分析、净值与回撤绩效评估。 |
| AI与技术 | 侧重技术层面：AI 工具（如 Claude, NotebookLM）应用、编程开发、自动化脚本、量化技术干货、AI Agent（Skills/MCP/RAG/Memory）。 |
| 新闻资讯 | 宏观新闻事件点评、行业突发新闻。 |
| 个人随笔 | 生活、运动（乒乓球）、学习方法、随感、认知进化。 |

### 2.5 兜底

AI 未返回任何分类时，使用「未分类」（`backend/app.py` L465-466）。

## 三、标签（Tags）生成

### 3.1 AI 从正文提取

DeepSeek `format_article` 根据**正文内容**提取 **5-8 个**核心标签（`deepseek.py` 的 `_build_format_prompt`），这是主来源。

### 3.2 量化文章的标签强化（prompt 注入）

`_build_format_prompt` 中检测正文/标题是否命中量化强信号词（`deepseek.py` L100-113）：

- 命中 → 向 prompt 注入「量化类文章标签规则」：从 `QUANT_TAG_POOL`（约 45 个量化词，与 app.py `TAG_KW` 一致）优先选取 3-6 个，**必须包含「量化」**，量化标签占多数。
- 未命中 → 走普通标签提取。

### 3.3 后端规则兜底

即使 AI 未提取出量化标签，只要标题/tags 命中 `TITLE_KW`/`TAG_KW`，后端 `_ensure_quant_tag` 也会强制补上「量化」「量化策略」（`app.py` L91-98）。**双层保障**：prompt 让 AI 主动选 + 后端兜底强制补。

### 3.4 小红书特殊处理

小红书解析文章（视频/图集）直接预设 `['小红书', '图集']` 等标签，跳过 AI（`app.py` L440）。

## 四、分类与标签的分工

| | 分类（Categories） | 标签（Tags） |
|---|---|---|
| **粒度** | 粗，文章归属（1-3 个） | 细，内容关键词（5-8 个） |
| **用途** | 归档、导航、统计 | 检索、关联推荐、标签云 |
| **来源** | 用户优先 → 规则 → AI | 正文提取（AI）+ 规则补充 |
| **Hugo 字段** | `categories: ["量化"]` | `tags: ["量化", "回测", ...]` |

## 五、输出与读取

- **写入**：统一写为 `categories: [...]` 列表（多分类），`category` 仅作兼容参数（`backend/utils/markdown.py`）。
- **读取**：管理后台优先读 front matter 的 `categories` 字段，而不是从文件名正则猜测（`backend/services/github.py` → `frontend/admin.js`）。

## 六、维护指南

- 想让更多文章归入「量化」或补更多量化标签 → 扩充 `backend/app.py` 的 `TITLE_KW`/`TAG_KW`，同时同步 `backend/services/deepseek.py` 的 `QUANT_TITLE_KW`/`QUANT_TAG_POOL`（两处需保持一致）。
- 调整分类体系 → 改 `backend/services/base_llm.py` 的 `PRESET_CATEGORIES`，并同步前端分类下拉框 `frontend/admin.html`。
